# ESP32 BME280 Meteostation

[English](README.md) | Русский

Метеостанция на **ESP32-WROOM-32** с датчиком BME280 и веб-интерфейсом для отображения температуры и влажности.

## Возможности

- Температура и влажность на главной странице, обновление каждые две секунды.
- Настройка Wi-Fi и давления на уровне моря через веб-интерфейс.
- Точка доступа для настройки и captive portal для Android, Apple и Windows.
- Английский и русский интерфейс; язык сохраняется на ESP32 и используется API.
- Сохранение Wi-Fi, опорного давления и языка после отключения питания.
- Светодиодная индикация состояния сети и датчика.
- Автоматическое восстановление Wi-Fi и повторный поиск BME280.
- Текст на выбранном языке и числовые показания `/get` для интеграций с Алисой, включая «Домовёнок Кузя».

## Подключение и прошивка

Потребуются плата **ESP32-WROOM-32** и **BME280 с интерфейсом I2C**. BMP280 не измеряет влажность и не поддерживается.

| Сигнал | ESP32-WROOM-32 |
| --- | --- |
| BME280 SDA | GPIO21 |
| BME280 SCL | GPIO22 |
| BME280 VCC | 3,3 В |
| BME280 GND | GND |
| Светодиод | GPIO2, включение уровнем HIGH |

Проверьте распиновку своей платы. В начале скетча заданы `BME_SDA_PIN`, `BME_SCL_PIN`, `STATUS_LED_PIN`, `STATUS_LED_ON` и `STATUS_LED_OFF`; при необходимости измените их. Для индикации предполагается светодиод на GPIO2 с активным уровнем HIGH. Адреса `0x76` и `0x77` определяются автоматически.

1. Установите **esp32 by Espressif Systems** через менеджер плат Arduino IDE.
2. Установите **Adafruit BME280 Library** через менеджер библиотек; зависимости установятся автоматически.
3. Откройте [ESP32_BME280_Meteostation.ino](ESP32_BME280_Meteostation/ESP32_BME280_Meteostation.ino).
4. Выберите **ESP32 Dev Module** и порт своей платы, загрузите скетч.
5. Откройте монитор порта на скорости **115200 бод**: там выводятся IP устройства и диагностика.

Wi-Fi, DNS, EEPROM и Wire входят в Arduino core для ESP32. ESPping не нужен.

## Первая настройка

После первого запуска подключитесь к сети устройства:

```text
SSID: ESP32-BME280-Meteostation
Пароль: password123
```

Название и пароль заданы константами `AP_SSID` и `AP_PASSWORD`. Captive portal откроет настройки; если окно не появилось, перейдите на [http://192.168.4.1](http://192.168.4.1).

<img width="825" height="733" alt="1790417241" src="https://github.com/user-attachments/assets/eec62404-2070-4b85-86b9-b9e3a5c6553c" />

Выберите EN или RU, укажите SSID и пароль своей Wi-Fi, опорное давление на уровне моря. Нажмите **Сохранить и перезапустить**. Пустой пароль допускается для открытой сети. SSID ограничен 32 байтами UTF-8; пароль WPA — 8–63 байта либо 64 шестнадцатеричных символа.

После перезапуска подключитесь к домашней сети и откройте IP ESP32 из монитора порта или роутера. Главная страница показывает температуру в °C и относительную влажность в %. Шестерёнка открывает `/settings`.

## Давление и язык

Давление на уровне моря по умолчанию — **1020,00 гПа**, допустимый диапазон — **800–1200 гПа**. Укажите текущее опорное давление для своей местности. Настройка используется для расчёта `altitude_m` в `/get` и `/status` и не заменяет фактически измеренное давление. Главная страница показывает только температуру и влажность.

Кнопки EN/RU сразу сохраняют язык в EEPROM ESP32 — без перезапуска и отправки настроек. Все браузеры и `/get` используют один сохранённый язык. По умолчанию выбран английский. Температура в обоих языках остаётся в градусах Цельсия; меняются подписи и формат чисел.

## API

Замените `<ESP32_IP>` локальным адресом устройства. HTTP-порт по умолчанию — **80**, задаётся через `WEB_PORT`.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/` | Показания; при активной AP — настройки |
| GET | `/settings` | Настройки Wi-Fi и опорного давления |
| GET | `/get` | Сообщение на сохранённом языке и числовые показания |
| GET | `/status` | Числовые показания и состояние датчика |
| GET | `/get_config` | Сохранённые настройки, язык и состояние AP |
| POST | `/save_config` | Сохранить настройки и перезапустить |
| POST | `/set_language` | Сохранить `en` или `ru` без перезапуска |
| POST | `/clear_config` | Сбросить настройки и перезапустить в AP |

`/get` возвращает `message` на выбранном языке и отдельные числовые показания. В сообщении значения округляются до целых:

```json
{
  "status": "ok",
  "message": "Температура: 23, Влажность: 45",
  "temperature": 23.4,
  "humidity": 45.2,
  "pressure_hpa": 1000.00,
  "altitude_m": 166.7
}
```

Если выбран английский:

```json
{
  "status": "ok",
  "message": "Temperature: 23, Humidity: 45",
  "temperature": 23.4,
  "humidity": 45.2,
  "pressure_hpa": 1000.00,
  "altitude_m": 166.7
}
```

При недоступном датчике `message` содержит ошибку на выбранном языке, все четыре числовых показания — `null`, поле `status` остаётся `ok`. В интеграциях вместо прежнего поля `data` нужно читать `message`.

Пример `/status`:

```json
{
  "sensor_ok": true,
  "language": "ru",
  "temperature": 23.4,
  "humidity": 45.2,
  "pressure_hpa": 1000.00,
  "altitude_m": 166.7,
  "ApMode": false
}
```

Ключи числовых полей не зависят от языка. Если датчик недоступен, `/status` возвращает `sensor_ok: false`; все четыре показания в `/get` и `/status` — `null`.

Сохранить язык:

```bash
curl -X POST http://<ESP32_IP>/set_language -d "language=ru"
```

Сохранить настройки (`language` необязателен; без него сохраняется текущий язык):

```bash
curl -X POST http://<ESP32_IP>/save_config --data-urlencode "ssid=Home Wi-Fi" --data-urlencode "password=your-password" -d "sea_level_pressure=1020.00" -d "language=ru"
```

Сбросить все настройки:

```bash
curl -X POST http://<ESP32_IP>/clear_config
```

Для `/save_config` обязательны `ssid`, `password` и `sea_level_pressure`. Некорректные данные возвращают HTTP 400, ошибка сохранения — HTTP 500. Успешное сохранение возвращает `{"status":"ok"}`. Ответ `/set_language` также содержит `language`.

`/get_config` включает сохранённый пароль Wi-Fi. Авторизации в интерфейсе и API нет; используйте доверенную локальную сеть.

## Светодиод и восстановление

| Индикация | Состояние |
| --- | --- |
| Постоянно горит | AP активна, основная Wi-Fi отключена |
| Меняет состояние каждые 250 мс | Подключение к основной Wi-Fi |
| Меняет состояние каждую секунду | Wi-Fi подключён, датчик отвечает |
| Пять быстрых вспышек, затем секунда без света | Wi-Fi подключён, датчик не отвечает |

Вспышка длится 100 мс, интервал между вспышками — 100 мс. Секундная пауза начинается после пятой вспышки.

При запуске с сохранёнными данными Wi-Fi подключается до трёх минут, затем включается AP. После потери уже установленного соединения AP включается через 30 секунд. Попытки подключения продолжаются при активной AP; после восстановления основной сети AP и captive DNS отключаются.

Отсутствующий датчик не блокирует настройку Wi-Fi и API. Показания обновляются каждые две секунды; повторный поиск недоступного датчика — каждые пять секунд. До восстановления вместо старых показаний выводится ошибка.

## Возможные проблемы

- **Нет показаний:** проверьте питание 3,3 В, землю, SDA/SCL и модель датчика. Оба адреса I2C проверяются автоматически.
- **Нет Wi-Fi:** нужна сеть 2,4 ГГц; проверьте данные через резервную AP.
- **Не открывается портал:** откройте `http://192.168.4.1`, подключившись к сети устройства.
- **Неверный язык:** выберите EN/RU на любой странице. Язык хранится на ESP32 и влияет на всех клиентов.
- **Неверная индикация:** проверьте GPIO и активный уровень LED своей платы.
